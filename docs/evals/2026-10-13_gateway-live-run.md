# 게이트웨이 실가동 확인 (Qwen + Jev, 2026-10-13)

> 평가 도구가 아니라 **게이트웨이 서버(HTTP)** 를 실제 모델로 켜서 요청을 보내 본 첫 확인입니다. 이전까지 서버는 mock과 자동 테스트로만 검증했습니다.

## 구성

| 항목 | 값 |
|---|---|
| 서버 | `uvicorn gateway.app:create_app --factory`, 포트 8800(정상 시나리오), 8801(장애 시나리오) |
| 라우팅 | `ROUTER_MODE=hybrid`, `ROUTER_PROMOTE_THRESHOLD=0.995` (이 실행에서만 환경변수로 덮어씀. 기본값 0.7은 Jev `p(easy)`가 최소 0.94라 전부 소형으로 간다) |
| 소형 / 상용 / 판정 | `qwen3.7-flash` / `qwen3.8-max` / Jev(`jev-1.13.0`), 정책 `v1` |
| 인증 | 이 실행용 임시 키(저장·출력하지 않음) |
| 저장소 | 별도 SQLite 파일(`data/live-demo.sqlite3`, `.gitignore` 대상) |
| 총 비용 | 약 $0.0004 (모델 호출 5회, 판정 호출 5회) |

## 결과

| 시나리오 | 응답 | 경로 | 이유(trace) | 비용 | 지연 |
|---|---|---|---|---|---|
| 프랑스의 수도 (영어) | 200 `Paris` | 소형 | `judge_easy`, `p(easy)`=1.0 | $0.00002 | 판정 284ms + 모델 909ms |
| 대한민국의 수도 (한국어) | 200 `서울` | 소형 | `judge_easy`, `p(easy)`=1.0 | $0.00002 | 판정 200ms + 모델 679ms |
| 다단계 속력 문제 (영어) | 200 `75` (정답) | **상용** | `promoted_low_confidence`, `p(easy)`=0.98 | $0.00016 | 판정 199ms + 모델 1625ms |
| 연속된 자연수 문제 (한국어) | 200 `26` (정답) | **상용** | `promoted_low_confidence`, `p(easy)`=0.99 | $0.00011 | 판정 196ms + 모델 857ms |
| 키워드 `analyze` | 200 `Positive` | 상용 | 규칙 `keyword:analyze`, **판정기 호출 없음** | $0.00007 | 모델 809ms |
| 프롬프트 인젝션 | **400** `input_blocked` | 모델 호출 없음 | 가드 `prompt_injection:ignore_previous` | $0 | 0ms |
| 공백만 입력 | **400** `input_blocked` | 모델 호출 없음 | 가드 `empty_input` | $0 | 0ms |
| 인증 헤더 없음 / 틀린 키 | **401** | - | 응답에 `X-Request-ID` 포함 | - | - |
| `stream: true` | **400** `stream_unsupported` | - | - | - | - |
| `messages: []` | **422** | - | - | - | - |

- 다단계 속력 문제는 평가에서 소형 모델이 틀렸던 문항(`en-math-05`, 60 대 정답 75)과 같은 문제입니다. 임계값 0.995에서 판정기가 상용으로 올려 보내 정답을 얻었습니다. 평가에서 본 순위 신호가 서버에서도 같은 방향으로 작동한 사례 1건입니다(통계적 증거는 아님).
- 모든 정상 요청에서 trace가 `guard → judge → router → provider` 순서로 저장됐고, 판정 확률·모델·토큰·비용·지연이 기록됐습니다. `router` 단계의 지연에는 판정기 호출 시간이 포함됩니다.
- 요청당 비용은 판정기가 약 $0.00002로 소형 모델($0.000001)의 약 20배입니다. 평가에서 본 판정 비용 부담이 서버에서도 확인됐습니다.

### 모델 장애 시나리오 (수정 전 동작)

소형 모델의 키를 일부러 잘못된 값으로 덮어쓰고 쉬운 질문을 보냈습니다. 아래는 mock fallback을 없애기 **전**의 결과이고, 수정 후 같은 장애를 다시 확인한 결과는 문서 끝의 [화면과 장애 시나리오 재확인](#화면과-장애-시나리오-재확인-같은-날)에 있습니다.

- 소형 호출이 `HTTP 401`로 실패했고(`provider error`, 과금 없음), 이어서 `fallback-mock`이 응답했습니다(`fallback: true`). 요청은 **200으로 성공**했습니다.
- 응답 내용은 `[fallback-mock] What is the capital of France? Answer with one word.` 로, 질문을 그대로 따라 말한 의미 없는 문장입니다.

## 확인된 요구사항

[product.md](../product.md)의 FR-1~FR-8이 실제 모델로 동작하는 것을 확인했습니다(FR-1은 일부 지원 범위 안에서).

## 발견한 문제

1. **[해결됨, 같은 날] fallback 응답이 의미 없는 echo인데 HTTP 200으로 나간다.** 클라이언트는 성공한 답으로 읽고, 장애 사실은 응답의 `model` 필드와 trace에서만 알 수 있다. 장애가 조용히 묻힌다. 후보: (a) 응답 헤더로 fallback 사용을 알린다(예: `X-LLMOps-Fallback`). (b) mock 대신 **다른 경로의 실제 모델**(소형이 죽으면 상용)로 먼저 대체한다. (c) 모든 실제 모델이 실패했을 때만 503을 돌려준다. 설계 결정이 필요하다.
   - **결정과 수정**: (b)+(a)를 채택했다. 소형이 죽으면 상용, 상용이 죽으면 소형이 대신 답하고, 모두 실패하면 502를 돌려준다. mock fallback은 운영 wiring에서 제거했다. 대신 답했는지는 `X-LLMOps-Fallback`, `model`, trace로 드러난다. 자동 테스트로 확인했고, 실제 모델로도 다시 확인했다(문서 끝 절).
2. **[해결됨, 같은 날] 401과 422의 오류 본문이 OpenAI 형식이 아니다.** 입력 가드와 스트리밍 거절은 `{"error": {"message", "type", "code"}}` 이지만, 인증 실패와 요청 검증 실패는 FastAPI 기본 형식 `{"detail": ...}` 이다. OpenAI SDK를 쓰는 클라이언트는 오류 본문을 일관되게 읽지 못한다.
   - **수정**: `gateway/errors.py`에서 HTTP 오류(401·404·405 등), 검증 오류(422), 처리되지 않은 예외(500)를 모두 `{"error": {message, type, param, code}}`로 바꿨다. 상태 코드는 그대로다(422는 OpenAI가 쓰는 400으로 바꾸지 않았다). 검증 오류는 필드 경로(`messages[0].role`)와 규칙 메시지만 담고 입력 값은 돌려주지 않는다. OpenAI SDK로 실제 호출해 보지는 않았고, 본문 모양은 자동 테스트로만 확인했다.
3. **기본 임계값(0.7)이 Jev와 맞지 않는다.** 서버를 `hybrid`로 켜도 기본값으로는 판정이 의미가 없다. 설정으로 0.99대로 올려야 한다. 정책 v2 이후 기본값을 정해야 한다.
4. **[부분 해결, 같은 날]** 응답에 선택된 경로와 판정 확률이 드러나지 않는다. → 응답 헤더 `X-LLMOps-Route`, `X-LLMOps-Route-Reason`, `X-LLMOps-P-Easy`를 추가했다. 과거 요청의 상세 조회는 여전히 없다(의도).
   - 원래 문제: trace는 DB에만 있고 조회 API는 의도적으로 없다. 시연 화면을 만들려면 응답 헤더나 별도의 안전한 조회 수단이 필요하다.

## 화면과 장애 시나리오 재확인 (같은 날)

시연 화면(`/demo`, React)을 만든 뒤, 같은 실제 모델(Qwen + Jev)로 서버를 켜고 **헤드리스 Edge가 화면의 버튼을 실제로 클릭**하게 해서 결과 카드와 이력 표를 읽었습니다. 서버 설정은 위와 같습니다(`hybrid`, τ=0.995, 임시 인증 키, 별도 SQLite).

### 장애 시나리오 (수정 후)

소형 모델의 키만 이 프로세스의 환경변수로 틀린 값으로 덮어쓰고(`.env`는 건드리지 않음) 같은 질문을 보냈습니다.

- 쉬운 질문(영어): 판정기는 쉬움(1.0)으로 판단해 **소형으로 라우팅**했고, 소형 호출이 `HTTP 401`로 실패한 뒤 **`qwen3.8-max`(상용)가 `Paris`로 대신 답했습니다.** HTTP 200이고, 화면에는 "라우터 선택: 소형 모델" 옆에 "장애로 다른 모델이 대신 답함" 배지와 이력 표의 ⚠, 요약의 "대체 응답 1"이 표시됐습니다.
- trace: `guard allow → judge easy(1.0) → router small → provider error(slm 401, 비용 0) → provider ok(openai/qwen3.8-max, fallback=true)`. 비용 $0.000074는 판정 비용에 **대신 답한 상용 모델의 단가**로 계산한 값입니다.
- 이어서 다단계 문제와 직접 입력한 질문(연속된 네 자연수의 합 98, 정답 26)은 상용 경로 그대로 정답을 냈고 대체 표시가 붙지 않았습니다.
- 첫 실가동에서는 같은 장애가 질문을 따라 말하는 `[fallback-mock] ...`을 HTTP 200으로 내보냈습니다. 이제는 실제 모델의 정답이 나가고 대체 사실이 응답 헤더·화면·trace에 드러납니다.

### 비용과 한계

- 두 실행의 모델 호출은 판정 7회, 모델 응답 8회(실패 1회 제외)이고 합계 약 $0.0007입니다(trace의 `cost_usd` 합계: $0.00038 + $0.00034).
- 이것은 헤드리스 브라우저(자동 클릭)로 본 결과이며, 사람이 일반 브라우저에서 눈으로 본 것은 아닙니다. 모바일 화면과 다른 브라우저는 보지 않았습니다.
- 정상 경로의 표본은 시나리오당 1회입니다. 판정 확률의 변동을 보려면 반복 측정이 필요합니다.
- 상용 모델이 실패하는 반대 방향(상용 → 소형)과 두 모델이 모두 실패하는 502는 자동 테스트로만 확인했고 실제 모델로는 시험하지 않았습니다.
