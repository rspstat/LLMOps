## 3. Trace 저장 방식 후보

**스키마(공통):** 단계마다 한 행씩 쌓는 `trace_events` 테이블 하나입니다. 2~4단계에서 이벤트 종류만 늘어나므로 마이그레이션이 필요 없습니다.

```
trace_events(id, request_id, seq, stage[guard|router|provider], decision,
             confidence, model, prompt_tokens, completion_tokens,
             cost_usd, latency_ms, detail_json, created_at)
```

| | A. SQLite 임시 사용 | B. 바로 PostgreSQL |
|---|---|---|
| 장점 | 설치와 의존성이 없어 바로 끝까지 관통됩니다. 테스트는 `tmp_path` 파일이나 `:memory:`로 빠르고 격리됩니다. 로드맵 1단계 목표인 "한 줄 관통"에 집중할 수 있습니다. | 최종 목표 스택과 일치해 나중에 옮길 일이 없습니다. JSONB와 동시 쓰기를 처음부터 쓸 수 있습니다. 발표에서 "실제 스택"이라고 말할 수 있습니다. |
| 단점 | 최종 스택이 아닙니다. 나중에 PostgreSQL 어댑터를 따로 만들어야 합니다. 동시 쓰기와 집계 성능에 한계가 있습니다. | 지금 환경에 docker와 psql이 없어 설치와 설정(Docker Desktop/WSL2 또는 네이티브)이 먼저입니다. 테스트에 DB 기동이나 testcontainers가 필요해 느리고 CI도 무거워집니다. 1단계 일정이 설치 문제로 밀릴 위험이 있습니다. |
| 마이그레이션 | `TraceStore` 인터페이스 뒤에 두고 SQL을 이식 가능하게 씁니다(JSON은 TEXT, 시각은 ISO 문자열). 같은 계약 테스트를 두 구현에 돌리면 `PostgresTraceStore` 추가는 파일 하나와 의존성 하나입니다. | 해당 없음 |

**추천은 A입니다.** 이유는 세 가지입니다.
- CLAUDE.md의 우선순위가 "끝까지 동작하는 한 줄 관통"입니다.
- 중간발표(11/5)까지 시간이 많지 않습니다.
- 저장소가 확정되면 `docs/architecture.md` 결정 기록에 남기라는 규칙이 있으므로, 이번에 "SQLite 임시 사용, 평가 단계(3단계) 전에 PostgreSQL로 교체"를 기록하는 편이 정직합니다.

PostgreSQL 이행 시점은 3단계(평가)에서 집계 쿼리가 필요해질 때가 자연스럽습니다.

**프라이버시 기본값:** 레포가 Public이고 trace에 프롬프트가 들어갈 수 있습니다. 기본은 프롬프트 본문을 저장하지 않고 길이와 해시만 저장합니다. 본문 저장은 `TRACE_STORE_CONTENT=true`로 켜는 옵션으로 두겠습니다. DB 파일은 `.gitignore`의 `*.sqlite3`에 이미 걸립니다.

## 4. 테스트 방식

- **원칙:** 모든 테스트는 mock이며 외부 API를 호출하지 않습니다. 비용이 드는 실제 호출은 `live` 마커로 분리하고 기본 실행에서 제외하며, 요청하실 때만 돌립니다.
- **단위 테스트:**
  - 입력 가드: 정상/빈 입력/길이 초과/인젝션 패턴과 임계값 설정 변경 시 동작
  - 라우터: 경계값
  - mock provider: 토큰과 지연 기록
  - `openai_compat`: `httpx.MockTransport`로 요청 형식 확인
  - 인증 401
- **TraceStore 계약 테스트:** 구현과 무관하게 쓰기, 요청 ID로 읽기, 순서 보존을 검증합니다. 나중에 PostgreSQL 구현에도 그대로 적용합니다.
- **E2E (TestClient):**
  1. 정상 요청이면 200이 오고, trace에 같은 요청 ID로 `guard → router → provider` 이벤트가 순서대로 있고 토큰·비용·지연이 채워져 있습니다.
  2. 인젝션 입력이면 400이 오고, guard 이벤트만 있고 provider 이벤트는 없습니다.
  3. provider가 실패하면 fallback으로 200이 오고, trace에 fallback 사실이 기록됩니다.
- **실행:** 변경 후 `pytest`와 `ruff check`, `ruff format --check`를 실제로 돌려 결과를 보고하겠습니다. 실패하면 원인과 함께 보고합니다.

| 1. SQLite + 교체 용이 | `DATABASE_URL` 하나로 저장소를 선택합니다. 기본값은 `sqlite:///./data/traces.sqlite3`입니다. `create_trace_store(url)` 팩토리는 `sqlite://`만 지원하고, `postgresql://`는 "미구현, 계획됨"이라는 명확한 오류를 냅니다. 앞서 제안한 `TRACE_DB_PATH`는 없앱니다. |
| 2. openai_compat 포함 | 테스트는 `httpx.MockTransport`만 씁니다. 실제 호출은 `scripts/smoke_live.py`에서만 하며 기본은 꺼져 있습니다. |
| 3. 엔드포인트 없음 | `/v1/traces`는 만들지 않습니다. 모든 응답(200/400/401/500 포함)에 `X-Request-ID` 헤더를 넣고, 저장소에는 `get(request_id)`를 둡니다. |
| 4. uv + 3.12 | `.python-version`은 `3.12`, `requires-python = ">=3.11"`, `uv.lock`은 커밋합니다. |

## 이식 가능한 trace 스키마

`trace_events` 한 테이블이고, 특정 DB에서만 되는 기능은 쓰지 않습니다.

| 컬럼 | 타입 | 비고 |
|---|---|---|
| `request_id` | TEXT | PK 일부 |
| `seq` | INTEGER | PK 일부. `AUTOINCREMENT` 같은 SQLite 전용 문법을 피하려고 (request_id, seq) 복합키를 씁니다 |
| `stage` | TEXT | guard, router, provider |
| `decision` | TEXT | |
| `confidence` | DOUBLE PRECISION | |
| `model` | TEXT | |
| `prompt_tokens`, `completion_tokens`, `latency_ms` | INTEGER | |
| `cost_usd` | DOUBLE PRECISION | |
| `detail_json` | TEXT | JSON 문자열. PostgreSQL에서는 나중에 JSONB로 변환 |
| `created_at` | TEXT | ISO-8601 UTC. PostgreSQL에서는 나중에 TIMESTAMPTZ로 변환 |

- 파라미터 표기(`?`와 `%s`)처럼 방언 차이는 `SqliteTraceStore` 안에 가둡니다.
- `get(request_id)`는 `seq` 순서로 정렬된 `list[TraceEvent]`를 돌려줍니다.
- `TraceStore` 계약 테스트는 구현과 무관하게 작성합니다. 나중에 PostgreSQL 구현이 생기면 같은 테스트를 그대로 돌립니다.
- 저널 모드는 기본값을 써서 `-wal`/`-shm` 부산물 파일이 생기지 않게 합니다. `.gitignore`의 `*.sqlite3`로 충분합니다.
- 프롬프트 본문은 기본적으로 저장하지 않습니다. 길이와 해시만 저장하고, `TRACE_STORE_CONTENT=true`일 때만 본문을 저장합니다.

## 실호출 안전장치

실제 호출이 일어날 수 있는 경로는 세 겹으로 막습니다.

1. **기본 provider는 mock입니다.** `SMALL_PROVIDER`와 `FRONTIER_PROVIDER` 기본값이 `mock`이라, `.env`에 키가 있어도 게이트웨이와 테스트는 외부를 호출하지 않습니다. 실 provider로 바꾸는 것은 설정으로 명시할 때만 가능합니다.
2. **테스트는 네트워크를 쓰지 않습니다.** `openai_compat`은 `httpx.MockTransport`로만 검증합니다. `scripts/`는 pytest 수집 대상이 아니고, `test_smoke_script.py`는 "플래그 없이 실행하면 네트워크 호출 없이 종료한다"만 확인합니다.
3. **`scripts/smoke_live.py`는 명시적으로 켰을 때만 동작합니다.**
   - 셸에서 호출 시점에만 `ALLOW_LIVE_CALLS=1`을 지정해야 합니다. `.env`에는 넣지 않습니다. `.env.example`에는 주석으로만 안내합니다.
   - `--target slm|frontier` 중 하나를 반드시 지정해야 합니다.
   - 요청은 1회, `max_tokens` 기본 16이며 상한 64로 강제합니다.
   - 타임아웃은 15초이고, 재시도는 하지 않습니다.
   - 키는 출력하지 않고, 대상 URL과 모델명 및 토큰 사용량만 보여 줍니다.
   - 플래그가 없으면 안내 메시지만 출력하고 종료합니다.
   - 저는 요청하실 때만 이 스크립트를 실행합니다.

- **새 의존성 없음.**

## 테스트 방식

- 모두 mock이고 네트워크를 쓰지 않습니다.
- Jev 어댑터는 `httpx.MockTransport`로 검증합니다.
  - 요청 본문 형태, 인증 헤더
  - 정상, 오류, 타임아웃, 잘못된 응답 파싱
  - 모르는 선택지나 확률 합 이상 등 이상값 거부
  - 키가 오류 메시지에 노출되지 않는지
- 라우터 단위 테스트 항목은 아래와 같습니다.
  - 규칙 hit이면 Jev 호출 0회
  - p=0.7이 경계에서 small
  - p<0.7이면 승격
  - hard이면 frontier
  - Jev 실패 시 규칙 대체
  - 모드별 동작
- E2E에서는 `judge → router → provider` trace 순서와 토큰·비용 기록을 확인합니다.
- 실제 Jev 호출은 스모크(`--target jev`)로만 하며, 요청하실 때만 실행합니다.

## 한계와 위험

- **mock 판정기는 품질 근거가 아닙니다.** 배관을 검증하는 용도이고, "Jev가 라우팅을 더 잘한다"는 주장은 3단계 평가 전에는 할 수 없습니다.
- **Jev 어댑터는 서드파티 문서 기반입니다.** 접근 권한(대기자 명단 또는 Vercel AI Gateway)이 승인돼 실제 호출로 확인하기 전까지는 "문서상 맞다"는 수준입니다. `docs/architecture.md`에도 그렇게 기록하겠습니다.
- **Jev 비용·지연 수치는 회사 발표값입니다.** 이번 단계에서는 trace에 실측을 쌓을 뿐 검증하지 않습니다.
