## 핵심 프롬프트

1. **계획 요청** — CLAUDE.md, README.md, docs/architecture.md를 먼저 읽고 0~1단계 계획(파일 목록, 의존성, trace 저장 방식 후보 SQLite vs PostgreSQL의 장단점, 테스트 방식)을 제시하되 승인 전에는 코드를 쓰지 말 것
2. **결정 전달** — trace는 SQLite로 하되 `TraceStore` 인터페이스 + DB URL 설정, 이식 가능한 컬럼 타입 / `openai_compat` 포함, 테스트는 mock HTTP만, 실호출은 명시적으로 켜는 수동 스모크 스크립트(낮은 max_tokens, 타임아웃) / `/v1/traces` 없이 `X-Request-ID` 헤더와 `get(request_id)` / uv로 Python 3.12 고정. 결정마다 `architecture.md` 결정 기록에 한 줄씩 추가하도록 계획을 갱신해 다시 제시할 것
3. **승인** → AI가 uv가 없음을 알려 설치 여부를 되물음 → **"설치해 줘. 그리고 커밋&푸시도 진행"**
4. **마무리 제안 수락** — 트러블슈팅 초안, AI 대화 기록 정리, 다음 단계(2단계) 진행 요청
5. **2단계 계획 승인** — "그렇게 해주세요" (승격 규칙은 단일 임계값, 판정 실패 시 규칙 결과로 대체, `judge_only` 모드 포함) + "Docker도 활용이 필요한가요?" 질문

## 2단계(라우팅 엔진 v1) 진행 기록

- **조사**: Jev 공식 문서를 못 찾아 서드파티 문서(LiteLLM, DigitalOcean)에서 `state`+`questions` 요청 형식과 `answers.<키>.choice/probabilities/confidence` 응답 형식을 확인. 공식 문서가 아니라는 점과 실호출 미검증을 코드 주석·결정 기록·README에 명시.
- **Docker 질문 답변**: 0~2단계에는 불필요, PostgreSQL·Qdrant 도입(3단계 전후)과 vLLM(WSL2/Docker 필요) 시점에 재검토 → 결정 기록에 반영.
- **구현**: `DecisionProvider`(생성용 `Provider`와 분리) → mock 판정기 → `JevProvider` → 정책(`router/policy.py`) → `HybridRouter` → 파이프라인 `judge` 이벤트 → 스모크 `--target jev`. 단계마다 pytest·ruff 통과 후 커밋 (최종 144개 테스트).
- **AI가 스스로 발견해 고친 것**:
  - 내가 쓴 테스트 하나가 `... or True`로 아무것도 검증하지 못하고 있었음 → 코루틴 함수 여부를 확인하는 실제 단언으로 교체.
  - 스모크 테스트에서 `monkeypatch.undo()`가 autouse 네트워크 차단 장치까지 해제하는 구조였음 → 테스트를 둘로 분리.
  - ruff B008(`Price()` 기본 인자) → 선택 인자 + 내부 기본값으로 수정.
- **실서버 확인**: `ROUTER_MODE=hybrid`로 uvicorn 실행 → 쉬운 요청(소형), 애매한 요청(`promoted_low_confidence`로 승격), 키워드 요청(판정기 호출 없음)을 HTTP로 확인하고 trace 행을 직접 조회.
- **하지 않은 것**: 실제 Jev/SLM/상용 API 호출(키·접근 권한 없음, 비용 규칙). mock 판정기는 요청 길이만 보므로 라우팅 품질의 근거가 아님.

6. **3단계 계획 승인** — "전부 추천대로 진행" (직접 작성 80개 데이터셋, 규칙 채점만, 3단계는 SQLite 유지, 모델·예산은 나중에) + "이 채팅 내역을 링크로 뽑아 줄 수 있나요? 대회에 AI chat log를 제출해야 합니다" 질문

## 3단계(평가 v1) 진행 기록

- **설계의 핵심**: 설정(모드 × τ)마다 모델을 다시 부르면 비용이 곱해지므로 `collect`(항목당 판정기·소형·상용 각 1회, 캐시)와 `report`(캐시 재생)로 분리. 재생은 라우팅을 다시 구현하지 않고 게이트웨이의 실제 `HybridRouter`를 녹화된 판정기와 함께 실행.
- **구현 순서**: 스키마·규칙 채점기 → 데이터셋 80개 → 캐시·수집(예산 가드) → 재생·지표 → 리포트·CLI → 문서. 단계마다 pytest·ruff 통과 후 커밋 (최종 458개 테스트).
- **데이터셋**: AI가 직접 작성(한·영 각 40, 5개 범주), 정답은 하나씩 계산해 확인. 난이도 라벨은 **검토 전**이라 메타파일과 리포트에 경고를 남김.
- **가장 의미 있는 발견**: mock(프롬프트를 따라 말함)으로 처음 리포트를 돌렸더니 정확도가 0%가 아니라 16.2%. 14개 문항이 프롬프트를 따라 말하기만 해도 정답이었고, 고친 뒤 재검사에서 선택지 나열(얼버무림) 답이 통과하는 구멍이 더 있었음 → `choice` + `options` + 얼버무림 규칙, 테스트로 고정 → [트러블슈팅](../troubleshooting/2026-10-13_채점-에코-통과.md).
- **리포트 설계 중 발견한 결함**: 모델을 바꿔 일부 항목만 다시 수집하면 서로 다른 모델의 결과가 한 설정으로 섞여 보고될 수 있었음 → 캐시 키와 메타데이터가 일치하는 기록만 사용하고 나머지는 stale로 표시.
- **계획 정정**: 앞서 "3단계 전 PostgreSQL 교체"라고 적었으나 설계해 보니 SQLite로 충분 → 결정 기록에서 정정(근거 포함).
- **실호출은 하지 않음**: 키·접근 권한이 없고 비용 규칙 때문. 평가 수치는 mock 기반이라 의미가 없으며, 리포트 상단과 README에 그렇게 표시.
- **AI가 반복한 실수 (정직하게 기록)**: 이번 세션에서 아무것도 검증하지 못하는 테스트 단언을 반복해서 썼다 — `... or True`(2건), `isinstance(...) or callable(...)`(1건, 실행했더니 실패해서 드러남), 도달할 수 없는 `if False else`(1건)와 쓰지 않는 변수. 모두 실행 전후 재검토나 실패로 발견해 고쳤지만, "테스트를 쓰고 나서 실행하기 전에 한 번 더 읽는다"는 습관 없이는 계속 생길 수 있는 유형이다.

## AI 응답 요약 / 채택한 내용

- **환경 점검 후 계획 수정**: docker/psql이 없고 시스템 `python`이 msys64와 3.14로 혼재함을 확인해, 처음부터 PostgreSQL을 쓰는 안의 위험을 근거로 SQLite 우선안을 추천했고 채택됨.
- **승인 없는 설치 보류**: uv가 없을 때 임의로 설치하지 않고 "설치해 줘"라는 명시적 승인을 받은 뒤 winget으로 설치.
- **작은 단위 구현**: 단계마다 `pytest` / `ruff`를 실제로 실행해 통과시킨 뒤 커밋 (총 13개 커밋). 최종 83개 테스트 통과.
- **구현 중 설계 변경**: 클라이언트 `X-Request-ID`를 trace 키로 쓰는 계획의 결함(재사용 시 저장 실패·오염)을 발견해 서버 생성 ID로 변경 → `docs/troubleshooting/2026-10-13_request-id-충돌.md`.
- **실서버 확인**: TestClient 외에 uvicorn으로 실제 HTTP 요청 → 200 / 400 응답과 SQLite 저장 행을 직접 확인.
- **실호출은 하지 않음**: `.env`와 키가 없어 스모크를 실행할 수 없었고, 비용 규칙(요청 시에만 실호출)에 따라 시도하지 않음. `openai_compat`은 mock HTTP로만 검증됨.
- **버린 것**: 처음 계획한 `TRACE_DB_PATH` 변수(→ `DATABASE_URL` 하나로 통일), setuptools 패키징(→ `package = false`), 잘못 쓴 `anyio_mode` pytest 옵션(실행 전에 발견해 제거).

## 확인이 필요한 것

- 실제 SLM·상용 API·Jev로 한 번씩 스모크 호출 (`ALLOW_LIVE_CALLS=1`, `.env` 설정 필요). Jev 어댑터는 이때 처음 실제 검증된다
- Jev 접근 권한(공식 대기자 명단, Vercel AI Gateway, DigitalOcean) 승인 여부
- 평가 데이터셋의 **난이도 라벨 검토** (끝나면 `evals/datasets/routing_v1.meta.json`의 `labels_reviewed`를 `true`로)
- 실제 소형·상용 모델과 Jev로 `collect` 실행 (모델 선택, `--budget-usd` 결정 필요) → 그 결과로 리포트·README의 수치 갱신
- Starlette의 `httpx2` deprecation 경고 대응 여부
