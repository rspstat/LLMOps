# 2026-10-13 · 설정 검증 오류가 API 키를 그대로 출력한다

## 증상

`evals.run check`(`.env`가 무엇을 하는지 설명하는 명령)의 테스트를 "출력에 비밀 값이 없어야 한다"로 썼더니, `.env`에 모순이 있는 경우(`SMALL_PROVIDER=slm`인데 `SLM_MODEL`이 비어 있음) 테스트가 실패했다. 출력에 **`SLM_API_KEY`의 실제 값이 평문으로** 들어 있었다.

```
error: 1 validation error for Settings
  Value error, SLM_MODEL is required when SMALL_PROVIDER=slm [type=value_error,
  input_value={..., 'slm_api_key': '<실제 키 문자열>'}, input_type=dict]
```

## 원인

pydantic의 `ValidationError` 기본 메시지는 검증 실패한 **입력 전체**(`input_value`)를 출력한다. `.env`에서 읽은 원시 문자열이 그대로 들어간다. `SecretStr`은 모델 객체를 `repr`할 때만 값을 가려 주고, 검증에 들어가는 입력은 가려 주지 않는다. 그래서 "비밀은 `SecretStr`로 선언했다"는 안심이 오류 경로에서는 틀렸다.

영향 경로는 설정을 읽는 모든 곳이다.

- `evals.run`(오류를 잡아 `error: ...`로 출력)
- 게이트웨이 서버 시작(uvicorn이 트레이스백을 출력)
- `scripts/smoke_live.py`(잡지 않아 트레이스백)

즉 `.env`를 잘못 채운 사용자가 터미널 출력을 그대로 채팅이나 이슈에 붙여넣으면 키가 노출된다. 이 프로젝트는 `.env` 값을 채팅에 붙여넣지 말라고 안내하지만 오류 메시지가 그것을 대신 해 주고 있었다.

## 시도한 것

| 대안 | 판단 |
|---|---|
| 각 CLI의 오류 처리에서 `loc`와 `msg`만 출력하도록 고친다 | **기각**: 경로마다 고쳐야 하고(서버 시작과 스모크 포함) 새 진입점이 생기면 다시 샐 수 있음 |
| `Settings`에 `hide_input_in_errors=True`를 설정한다 | **채택**: 설정 클래스 한 곳에서 모든 경로를 막음 |

## 해결

- `gateway/settings.py`: `SettingsConfigDict(..., hide_input_in_errors=True)`. 오류 메시지에서 `input_value`가 사라지고 `input_type`만 남는다.
- 테스트: `tests/test_settings.py`의 `test_a_validation_error_never_prints_the_raw_input`이 네 가지 실패 유형(모델 누락 2종, 키 누락, 범위 초과)에서 키 값이 메시지에 없음을 확인한다. `tests/test_eval_check.py`는 `check`의 모든 출력에서 비밀 값이 없음을 확인한다.
- 같이 추가: `evals.run check`. 키를 채웠는데 provider 스위치가 `mock`이라 아무 일도 일어나지 않는 상황, 이 프로젝트가 읽지 않는 키(`ANTHROPIC_API_KEY` 등), 오타 난 변수 이름을 비밀 값 없이 알려 준다.

## 배운 점

- **`SecretStr`은 `repr`만 가린다.** 비밀을 다루는 코드는 오류 경로, 예외 메시지, 트레이스백까지 "출력에 비밀이 없다"를 테스트로 확인해야 한다. 이번 발견은 새 기능의 테스트를 그 방식으로 썼기 때문에 잡혔다.
- 고치는 위치는 증상이 보인 곳(CLI)이 아니라 원인이 있는 곳(설정 클래스)이어야 다른 진입점이 같이 막힌다.
- 진단 도구를 만들 때는 "도구 자신이 비밀을 새게 하지 않는가"를 먼저 시험한다.

## 점검한 범위와 못 한 것

- 점검: `Settings` 검증 오류의 출력(4가지 유형), `check`의 출력.
- 점검하지 않음: 외부 라이브러리 예외(httpx 등)의 메시지에 인증 헤더가 들어가는지, 제공사 오류 본문에 요청 내용이 에코되는지. 어댑터는 오류 본문을 200자까지만 담고 키를 직접 넣지 않지만, 제공사가 본문에 키를 되돌려 주는 경우는 확인하지 못했다.
