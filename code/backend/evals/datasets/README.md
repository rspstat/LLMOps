# routing_v1 — 라우팅 평가 데이터셋

`routing_v1.jsonl`: 80개 프롬프트 (영어 40 + 한국어 40). 소형 모델로 충분한 요청과 상용 모델이 필요한 요청을 구분하는 **라우팅 설정을 비교**하기 위한 것이며, 모델 성능 벤치마크가 아닙니다.

## 출처와 상태

- **AI(Claude)가 이 레포를 위해 처음부터 작성**했습니다. 외부 데이터셋, 학교 비공개 자료, 개인정보는 사용하지 않았습니다. 한국어 항목은 영어 항목의 번역이 아니라 별도로 쓴 것입니다.
- 정답(`reference`)은 하나씩 직접 계산·확인했지만 **난이도 라벨(`difficulty`)은 검토 전 초안**입니다. 검토를 마치면 `routing_v1.meta.json`의 `labels_reviewed`를 `true`로 바꾸세요. `false`인 동안 리포트에 경고가 표시됩니다.

## 구성

| 범주 (`category`) | 내용 | 언어당 개수 (쉬움/어려움) |
|---|---|---|
| `factual` | 사실 질의 (어려움 = 두 단계 추론이 필요한 사실) | 8 (5/3) |
| `transform` | 번역, 철자 교정, 문장 변환 | 8 (5/3) |
| `math` | 사칙연산, 문장제 | 8 (4/4) |
| `classify` | 감정·분야·스팸 분류, 모순 판정, 문법 판단 | 8 (4/4) |
| `reasoning` | 수열, 순서 추론, 코드 출력 예측, 퍼즐 | 8 (4/4) |

모든 프롬프트는 답만 출력하도록 지시해서 규칙 채점이 가능합니다.

| `answer_type` | 채점 |
|---|---|
| `exact` | 정규화 후 참조 답과 완전 일치 |
| `number` | 답 전체 또는 마지막 숫자가 참조와 같음 (콤마·단위 허용) |
| `choice` | 답 전체 또는 첫 단어가 참조 중 하나. 한글 선택지(2자 이상)는 조사·어미가 붙어도 인정("민수가", "긍정입니다"). **`options`(프롬프트가 제시한 선택지)가 있고 답의 첫 세 단어 안에 서로 다른 선택지가 둘 이상 나오면 얼버무림으로 보고 오답** |
| `contains` | 답 안에 참조 중 하나가 포함 (참조가 프롬프트에 나오지 않는 문항에만 사용) |
| `open` | 규칙으로 채점 불가 → 정확도에서 제외 (v1에는 없음) |

정규화는 NFKC, 소문자화, 공백 정리, 앞뒤 구두점·마크다운 제거입니다 (`evals/scorers.py`).

### 채점 규칙 검증 (왜 `choice`와 `options`가 있는가)

mock provider(프롬프트를 그대로 따라 말함)로 첫 리포트를 돌렸더니 정확도가 0%가 아니라 16.2%였습니다. 원인을 찾아보니 14개 문항이 **프롬프트를 따라 말하기만 해도 정답**이었습니다. 12개는 `contains` 참조가 프롬프트의 선택지에 들어 있었고(`'긍정' 또는 '부정'`에서 `긍정`), 2개는 정답이 피연산자와 같았습니다(144÷12=12). 선택지를 나열하는 얼버무림 답("positive or negative")도 정답이 첫 번째 선택지면 통과했습니다.

고친 내용: 해당 문항을 `choice`로 바꾸고, 정답이 피연산자와 같던 두 문항의 숫자를 바꿨고(`156÷12=13`, `273÷13=21`), 모든 `choice` 문항에 `options`를 넣었습니다. `tests/test_eval_dataset.py`가 이를 고정합니다: 프롬프트 반복과 모든 선택지 나열 조합이 어떤 문항에서도 정답이 되지 않아야 합니다.

**알려진 비용**: 첫 세 단어 안에 다른 선택지를 함께 언급한 정상 답("민수는 지영보다 큽니다")도 오답이 됩니다. 소형·상용 모델에 똑같이 적용되므로 비교는 공정하지만 절대 정확도는 약간 낮게 나올 수 있습니다.

## 라벨의 의미

- `difficulty`: 작성자가 판단한 "소형 모델이 이 요청을 상용 모델만큼 잘 답할 수 있는가" (`easy` / `hard`). **측정값이 아니라 가설**입니다.
- 측정값은 평가 시 소형 모델이 실제로 정답을 냈는지입니다. 리포트는 판정기를 두 기준으로 모두 평가합니다 (작성자 라벨, 소형 모델 실제 정답).

## 알려진 한계

- **표본이 작습니다 (n=80).** 설정 간 차이는 신뢰구간을 함께 봐야 하며 "경향" 이상으로 해석하면 안 됩니다.
- **짧은 정답이 있는 문제만** 있습니다. 긴 생성, 요약, 창작처럼 규칙으로 채점할 수 없는 요청은 포함되지 않아서 "상용 모델이 꼭 필요한 요청"이 과소 대표됩니다.
- **규칙 라우터와의 상호작용을 일부러 넣었습니다.** 기본 키워드 규칙(`analyze`, `분석` 등)이 걸리는 프롬프트가 9개 있습니다 (쉬움 4, 어려움 5). 쉬운 문제에 걸리면 불필요하게 상용 모델로 가고, 키워드가 없는 어려운 문제는 규칙이 놓칩니다. 이 중 `en-transform-07`은 의도하지 않은 오탐입니다: 키워드 `prove`가 `approved`의 일부로 걸립니다. 키워드 규칙이 부분 문자열 일치라서 생기는 실제 동작이므로 고치지 않고 남겨 두었습니다.
- 작성자(AI)가 풀기 쉬운 유형에 치우쳤을 수 있습니다.

## 보류 데이터 (`routing_v1_holdout`)

`routing_v1_holdout.jsonl`: 60개 (영어 30 + 한국어 30, 범주 5개 × 쉬움/어려움 3개씩). 판정 정책 v2를 **한 번만** 검증하려고 v2 문구를 쓰기 전에 만들어 동결했습니다.

- `routing_v1`(80개)은 v1 평가에서 이미 다 봤고 임계값도 그 데이터에서 골랐으므로 **개발용**입니다. 정책 후보 비교는 여기서만 합니다.
- 보류 데이터로는 정책이나 임계값을 고르지 않습니다. 개발용에서 정한 정책과 τ를 그대로 적용해 v1과 v2를 각각 한 번씩만 측정합니다.
- 이 파일도 AI가 쓴 초안이고 난이도 라벨은 검토 전입니다(`labels_reviewed=false`). 숫자·코드 정답은 손으로 적지 않고 스크립트로 계산했습니다.
- `tests/test_eval_holdout.py`가 개발용과 겹치지 않음, 채점 구멍(프롬프트 따라 말하기, 선택지 나열)이 없음, 키워드 규칙에 우연히 걸리는 문항이 없음을 고정합니다. 이 테스트를 만들 때 개발용과 똑같은 프롬프트 3개를 실수로 다시 쓴 것을 잡아냈습니다.
- 한계: 60개라 신뢰구간이 넓어 작은 차이는 구분되지 않습니다. 작성자(AI)가 개발용 결과를 본 뒤 썼으므로 난이도 감각이 비슷할 수 있습니다.
